# 07 - 壳里面是什么

这个程序的比较逻辑被人为地"弄乱"了——里面塞了一堆永远不执行的死代码、一个看起来像是判断但实际上什么也没检查的条件、以及一个绕了好几圈的 key 计算过程。

## 你能学到什么

- 识别"不透明谓词"（opaque predicate）：一个总是为真或为假的表达式，专门用来迷惑反编译器
- 区分有效代码和垃圾代码
- 从复杂的表达式中提取真正有用的计算

## 题目特征

```c
// 这就是个 opaque predicate——i * (i+1) 对连续整数来说永远是偶数
int x = (i * i + i) % 2;
if (x) return 0;  // 永远进不去

// key 的计算绕了好几圈，但化简后只跟 i 有关
int k = i + 0xab;
k = (k * 7 + 11) & 0xff;
k ^= 0x55;
k = (k + 0x37) & 0xff;
k ^= 0xcd;
```

> 这种混淆手法在实战中非常常见。商业壳（VMP、Themida）做的混淆比这个复杂一百倍，但核心思想是一样的：**把简单的逻辑藏在一堆没用的运算里**。你能做的就是盯着看，把死代码一条条划掉，直到剩下真正干活的那几行。
